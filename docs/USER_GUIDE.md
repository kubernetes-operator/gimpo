## 1. 처음 접속하기

1. 주소로 들어가면 **로그인 화면**이 나옵니다.
2. 처음 한 번은 **최초 관리자 등록**을 합니다(canggu 관리자 확인 필요).
3. 이후 관리자가 **사용자 관리**에서 다른 사람 계정을 만들고, 볼 수 있는 페이지를 정해 줍니다.

| 역할 | 할 수 있는 것 |
|---|---|
| 관리자 | 모든 페이지, 백업·복구 실행, 스케줄 편집, 설정 변경, 사용자 관리 |
| 일반 사용자 | 허용된 페이지 **조회만** (실행·변경 버튼이 보이지 않습니다) |

## 3. 화면별 사용법

### 3.1 개요
맨 위 배너가 전체 상태입니다. 🟢 "백업·복구 정상" 이면 끝. 🟡/🔴 이면 배너를 눌러 **상태 점검**으로 이동하세요.

### 3.2 상태 점검
- **점검 항목**: 빨간 항목이 위에 옵니다. "내용" 칸에 이유가 적혀 있습니다. 1분마다 자동 갱신, 즉시 확인은 **지금 점검**.
- **스케줄별 백업 상태**: 스케줄마다 최근 결과·마지막 성공·다음 실행·저장 위치.
- **자동 복구 테스트**: 매일 05:00 에 테스트 데이터로 "백업 → 삭제 → 복구 → 비교"를 합니다.
  - **지금 실행**: 바로 테스트(1~3분). 진행 단계가 화면에 표시됩니다.
  - **설정**: 켜기/끄기, 실행 시각(한국 시간), 저장 위치, 제한 시간.
  - 이력 행의 ▸ 를 누르면 단계별 결과와 테스트 데이터(날짜 포함)를 볼 수 있습니다.

### 3.3 백업
- 행의 **상세**: 포함된 리소스 목록, 볼륨, 경고·오류.
- **로그**: Velero 가 남긴 실행 로그.
- **복구**: 이 백업으로 복구 화면을 엽니다.
- **백업 생성**: 대상 네임스페이스·리소스·저장 위치·보관 기간을 정해 바로 백업. *볼륨 데이터까지 받으려면 "파일시스템 백업 기본값"을 켜고 저장 위치를 `seaweedfs-lab` 으로.*

### 3.4 복구
**복구 생성** 에서:
1. 소스 백업을 고릅니다(Completed 백업만 표시).
2. 포함 네임스페이스에 복구할 앱 NS 를 고릅니다.
3. 원본을 건드리지 않고 확인하려면 **네임스페이스 매핑**에 `demo-app=demo-app-check` 처럼 입력합니다.
4. **복구 실행**. 결과는 목록에서 상태·errors/warnings 로 확인, **로그** 로 자세히.

> 팁: 확인용 복구는 HTTPRoute·Ingress·Job 을 "제외 리소스"로 빼면 실제 서비스와 충돌하지 않습니다.

### 3.5 스케줄
| 칸 | 뜻 |
|---|---|
| 이름 | 굵은 글씨가 **표시 이름**, 아래 작은 글씨가 실제 이름 |
| 일정 (한국 시간) | 예: "매일 03:00", "매월 2일 04:03" |
| 다음 실행 | 다음 백업 시각 |
| 저장 위치 / 보관 | 어느 저장소에 몇 일 |

- **편집**: 표시 이름·설명, 실행 일정(매일/매주/매월/직접 입력 — 한국 시간), 백업 대상·저장 위치·보관 기간을 바꿉니다. 저장 전에 다음 실행 시각 3개를 미리 보여 줍니다.
- **실제 이름 변경**(편집 안의 체크박스): Velero 는 이름을 바꿀 수 없어서 "새로 만들고 기존 삭제"가 됩니다. 기존 백업 처리를 고르세요.
  - *이력에 연결*(권장): 과거 백업을 새 이름의 **이력**에서 함께 봅니다.
  - *유지만*: 백업은 남지만 새 이력에는 안 보입니다.
  - *삭제*: 기존 백업을 지웁니다(되돌릴 수 없음).
  - Helm 으로 만든 스케줄은 Helm values 이름도 바꾸라는 경고가 뜹니다.
- **이력**: 그 스케줄의 백업 목록. "이전 이름의 백업도 보기"로 과거 이름 백업 포함.
- **즉시 실행**: 스케줄 설정 그대로 지금 백업.

### 3.6 스토리지 위치
| 이름 | 저장소 | 용도 |
|---|---|---|
| `default` | MinIO `osc-backup` | 설정(YAML) 백업, 기본 위치 |
| `seaweedfs-lab` | SeaweedFS `velero-backups` | PVC 데이터 백업, 복구 테스트 |

상태가 **Available** 이어야 정상입니다.

### 3.7 etcd 백업
etcd 는 쿠버네티스 **전체 상태**가 저장된 곳입니다. 이 화면의 스냅샷은 **클러스터 전체를 한 시점으로 되돌릴 때** 씁니다. 앱 하나는 복구 메뉴(Velero)를 쓰세요.

- **요약 카드**: 최근 스냅샷 결과, 보관 중인 스냅샷 수·용량, 멤버 응답(예: 3/3)·버전·리더, 최근 복원 연습 결과.
- **멤버 상태**: etcd1~3 의 주소·리더 여부·DB 크기·상태.
- **자동 실행 일정**: 스냅샷 6시간마다, 복원 연습 매일 05:30 (일정은 Git 에서 변경).
- **지금 스냅샷**(관리자): 업그레이드·대규모 변경 **직전에** 누르세요. 보통 1분 안에 끝납니다.
- **지금 복원 연습**(관리자): 최신 스냅샷을 임시 etcd 에 복원해 검증합니다. 운영 etcd 는 건드리지 않습니다.
- **스냅샷 이력**: ▸ 로 sha256·리비전·저장 위치. 행 오른쪽
  - *이 스냅샷으로 연습* — 특정 스냅샷이 복원되는지 확인
  - *절차서* — 그 스냅샷으로 되돌리는 **롤백 절차서**
- **복원 연습 이력**: ▸ 로 검증 항목(무결성·해시·복원·기동·리비전·핵심 키·네임스페이스 수).

#### 롤백 절차서
- 이 클러스터의 실제 값(멤버 이름·주소·토큰·데이터 폴더)이 채워진 단계별 명령이 나옵니다.
- **전체 절차** 탭과 **노드별(4단계)** 탭, *복사*·*Markdown 저장* 버튼이 있습니다.
- ⚠️ 웹에서 실행되지 않습니다. 운영자가 컨트롤 플레인 노드에 접속해 순서대로 실행합니다(운영 매뉴얼 7.3).

## 4. 자주 하는 일

| 하고 싶은 것 | 방법 |
|---|---|
| 어젯밤 백업이 잘 됐나? | 개요 배너 🟢 → 자세히는 상태 점검 "스케줄별 백업 상태" |
| 실수로 지운 앱 되살리기 | 복구 → 복구 생성 → 최신 앱 데이터 백업 → 해당 NS → 복구 실행 |
| 복구 전에 내용만 보기 | 복구 생성 시 네임스페이스 매핑 `원본=원본-check` → 확인 후 그 NS 삭제 |
| 백업 시각 바꾸기 | 스케줄 → 편집 → 실행 일정(한국 시간) → 저장 |
| 스케줄 이름 알아보기 쉽게 | 스케줄 → 편집 → 표시 이름 |
| 복구가 실제로 되는지 확인 | 상태 점검 → 자동 복구 테스트 → 지금 실행 |
| 쿠버네티스 업그레이드 전 대비 | etcd 백업 → 지금 스냅샷 → 이 스냅샷으로 연습 성공 확인 |
| 클러스터 전체 되돌리기 준비 | etcd 백업 → 스냅샷 이력 → 절차서 → Markdown 저장 |

## 5. 용어

| 용어 | 뜻 |
|---|---|
| Velero | 쿠버네티스 리소스·볼륨을 백업·복구하는 도구 |
| BSL(저장 위치) | 백업이 저장되는 곳(MinIO, SeaweedFS 버킷) |
| PVC 데이터 | 앱이 디스크에 저장한 실제 데이터(DB, 파일 등) |
| Completed / PartiallyFailed | 백업 완전 성공 / 일부 항목 실패(대부분 확인 필요) |
| etcd | 쿠버네티스의 모든 설정·상태가 저장되는 데이터베이스 |
| 스냅샷 | etcd 를 한 시점에 통째로 저장한 파일 |
| 복원 연습 | 스냅샷을 임시로 복원해 실제로 쓸 수 있는지 확인하는 것 |
