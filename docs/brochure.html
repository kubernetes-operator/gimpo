Why

문제는 백업 도구가 아니라 "보이지 않는 것"이었습니다

도입 전 이 클러스터에서는 설정 오류로 몇 주간 모든 백업이 실패했고, 볼륨 백업 하나가 13일째 멈춰 뒤로 17건이 밀렸으며, 삭제 요청 79건이 쌓여 있었습니다. 아무도 몰랐습니다.

Design

세 겹 백업, 서로 다른 저장소

설정과 데이터를 물리적으로 다른 저장소에 둡니다. 한쪽이 망가져도 다른 쪽이 남고, 앱 데이터 백업은 그 자체로 완결돼 복구가 한 번에 끝납니다.

Proof

"복구된다"를 이렇게 확인합니다

Velero 자동 복구 테스트 · 매일 05:00

  1. 그날 날짜가 찍힌 Pod·디스크·설정·비밀 생성
  2. 데이터 저장소로 백업
  3. 전부 삭제해 장애 재현
  4. 백업에서 복구
  5. 설정·비밀·파일·1MiB 데이터 지문(sha256) 비교
  6. 복구된 디스크가 "새로 쓴 것"이 아닌지 확인 후 정리
✓ 실제 클러스터 · 전 단계 일치 · 28초

etcd 복원 연습 · 매일 05:30

  • 내려받은 스냅샷 sha256 이 원본과 일치
  • 스냅샷 해시 검증
  • 임시 etcd 로 복원·기동 (운영 etcd 무접촉)
  • 리비전 일치 · 핵심 키 존재 · 네임스페이스 수 일치

스냅샷마다 이 클러스터 값이 채워진 롤백 절차서를 만들어 줍니다. 3노드 클러스터에서 그 명령 그대로 실행해, 사고 후 변경이 스냅샷 시점으로 정확히 돌아가는 것을 확인했습니다.

Features

운영하는 사람을 위한 기능

신호등 상태 점검

서버·저장소·스케줄·멈춘 작업·복구 검증·etcd 를 1분마다. 예정 시각에 백업이 안 돌면 바로 빨간불.

한국 시간 스케줄

매일·매주·매월과 시각을 고르면 다음 실행 3회를 미리 보여 줍니다.

표시 이름과 이력

알아보기 쉬운 이름을 붙이고, 이름을 바꿔도 과거 백업을 이어서 봅니다.

옆에 복구해 보기

네임스페이스를 바꿔 원본 옆에 복구하고, 확인한 뒤 실제 복구합니다.

etcd 롤백 절차서

노드별 명령·확인 명령·되돌리기까지. 위험한 작업은 웹에서 실행하지 않습니다.

로그인과 페이지 권한

관리자만 실행·변경, 일반 사용자는 허용된 화면만 조회. 비밀 값은 어디에도 남기지 않습니다.
